# 实践手册：导读

> 这份手册回答一个问题：**为什么智能体「看起来很聪明」，却守不住工程与架构约束？以及一线团队是怎么解决的。**

## 一句话结论

一线团队（Anthropic、OpenAI、Google、Meta、GitHub、Cursor、Cognition、Thoughtworks，以及美团、蚂蚁、快手等）在 2025–2026 年逐步收敛到同一个判断：

> **约束不能靠「告诉」模型，而要靠「环境」强制。** 把能机械检查的规则变成 linter、结构测试、hook 与 CI 门禁；把只能靠判断的知识写成精简、按需加载的上下文；把人的注意力从「逐行读代码」转移到「设计 harness、评审计划、为高风险变更把关」。

OpenAI 称之为 harness engineering（[OA01](/sources/openai#oa01)），Thoughtworks 称之为 guides（前馈）+ sensors（反馈）（[TW01](/sources/thoughtworks#tw01)），Anthropic 的文档把它表述为「非确定性指令 vs 确定性指令」（[AN01](/sources/anthropic#an01)）。说法不同，内核一致。

## 你遇到的问题，大概率不是模型「不够聪明」

如果你有多年开发经验，觉得智能体「不守规矩」，下面几个事实值得先知道：

1. **写在 CLAUDE.md / AGENTS.md 里的规则只是「建议」。** Anthropic 自己的文档说得很直白：无论措辞多强，某一轮是否遵守，仍然由模型决定（[AN01](/sources/anthropic#an01)）。
2. **规则越多越不听话。** 指令有容量上限（[VD19](/sources/vendors#vd19)），冲突的指令会让模型反复权衡（[X07](/sources/x-posts#x07)），长上下文会「腐化」（[PR36](/sources/practitioners#pr36)）；会话越长，遵守率越低（[RS07](/sources/research#rs07)）。
3. **智能体会复制仓库里已有的坏模式。** OpenAI 团队曾每周花 20% 时间清理「AI slop」（[OA01](/sources/openai#oa01)）；GitClear 数据显示复制粘贴代码上升、重构下降（[RS05](/sources/research#rs05)）。
4. **它会为了「完成」而作弊。** 删除或禁用测试（[PR15](/sources/practitioners#pr15)）、测试失败时宣告成功（[TW14](/sources/thoughtworks#tw14)）、为编译通过跳过代码检查（[CN06](/sources/chinese#cn06)）。
5. **你感觉到的提效不能当证据。** METR 2025 年初的对照实验里，资深开发者用 AI 慢了 19%，却自认为快了 20%（[RS01](/sources/research#rs01)）。2026-02 的后续实验点估计已转为加速，但置信区间跨过 0，METR 自己也说因选择效应而不可靠（[RS09](/sources/research#rs09)）。不变的结论是：体感不可靠，要用交付指标度量（第 08 章）。

这些都是**系统设计问题**，而系统设计正是资深工程师的强项。

## 关于证据强度

本手册大量依赖厂商与个人的经验报告，真正的对照研究很少，而且彼此有冲突。我们用三个标记提醒读者：

- **共识**：多家独立来源给出一致建议。
- **分歧**：存在可信的相反证据或观点，会并列呈现。
- **待验证**：只有单一来源或厂商自报数据。

2026-11 起，每章对比表新增「佐证」列，给出相关原则的**独立支持作者数／异议数**（基于全量库中较早收录的 2,223 条资料的关键词归类；全量库现有 3,195 条，后来新增的质量专题与中文大厂资料没有计入 P01–P20，第 12 章另用 Q01–Q13 统计质量专题）。统计口径与每条原则的代表性来源、人工确认的异议，见 [共识度/佐证](/compare/evidence)。**注意：「支持」数是关键词自动归类的结果，只要提到相关关键词、又没有否定措辞的条目都会被计入，没有逐条人工复核；只有「人工确认的异议」是逐条阅读的。** 请只把它当作量级参考，例如 300 和 50 的差别有意义，260 和 250 的差别没有意义。各章新增的「2026-11 新证据」小节说明了哪些结论因此被加强、哪些被修正。
